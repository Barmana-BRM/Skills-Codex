# 木材非局部损伤 Abaqus 架构路由器

## I — 方法论骨架

1. 先冻结非局部或梯度方程，再选择 Abaqus 载体；不能从熟悉的子程序反推物理模型。
2. 纯 UMAT 在积分点局部调用，通常不能自行访问当前增量的任意邻域场。
3. `STATEV` 是本积分点历史，不是自动空间平均量；把局部历史改名为 nonlocal 不会产生邻域耦合。
4. UMAT+UMATHT 可借用附加标量场和扩散型方程，但每个场都要有明确变量映射、源项、通量和边界条件。
5. 多个独立非局部变量、强交叉耦合或特殊边界可能需要 UEL、全局邻域装配或其他更直接的架构。
6. 架构选择必须闭合“谁产生局部驱动力、谁求解空间场、谁读回、何时同步、失败如何回滚”。
7. 验收需要解析场、单元基准、网格/边界敏感性和结构问题，不能只看作业完成。

## A2 — 触发与路由

在以下场景调用：

- 已选择积分非局部或梯度损伤，却只准备写一个局部 UMAT。
- 想用 UMATHT 承载一个或多个非局部驱动力，但不清楚字段数量和耦合方向。
- 需要邻域搜索、核平均、附加 PDE、非局部边界修正或并行同步。
- 局部 `STATEV` 被当成邻域平均值，或不同求解器字段在增量内读取时序不清。
- 需要在 UMAT+UMATHT、UEL 和全局邻域机制之间比较实现成本与信息闭包。

物理路线尚未冻结时先用 `wood-cdm-spatial-regularization-router`。纯局部裂带且信息闭包已满足时，不要无故升级架构。

## 输入与输出合同

必需输入：空间正则化方程、非局部变量数量与单位、局部源量、核/梯度系数、边界条件、耦合强度、求解器和并行预算、方向场接口。

输出：

- 数据流图：局部驱动力、空间求解、读回、状态提交和回滚。
- UMAT、UMATHT、UEL 或全局邻域架构路由及拒绝理由。
- 字段/自由度/状态变量表与调用时序。
- 最小解析、单元、网格、边界和结构验证矩阵。
- `ARCHITECTURE_CLOSED`、`PASS_WITH_LIMITS` 或 `BLOCKED_BY_INTERFACE`。

## E — 执行步骤

1. 写出每个非局部变量的方程、单位、源项、通量/核、内长度和边界条件。
2. 画出局部积分点到空间场再回到损伤更新的数据流，标明时间层和迭代层。
3. 审计纯 UMAT 是否能取得所需邻域信息；不能时明确阻断，而不是复用本地 `STATEV`。
4. 单一扩散型标量且耦合可接受时评估 UMAT+UMATHT；冻结温度/场变量的物理映射和冲突风险。
5. 多场、强耦合、特殊插值或非标准边界时比较 UEL 与全局邻域实现。
6. 定义所有字段、自由度、`STATEV`、共享数据和失败回滚的唯一写入者。
7. 用常量场、线性场、解析扩散/Helmholtz 场和单元拼接检查单位、符号、边界与同步。
8. 在多网格、多边界距离和并行分区下复测空间场、损伤带、能量与收敛。

## B — 边界

- 本 skill 不选择裂带、积分非局部或梯度路线，只承载已经冻结的方程。
- UMATHT 是可复用的标量场载体，不代表任意多场和任意强耦合都自然闭合。
- 通过共享文件或非线程安全全局数组交换邻域量会引入并行、顺序和重启风险。
- 本地历史、预处理方向场和求解中非局部场是三类不同数据，不得混装。
- 架构能运行不证明空间模型已标定或网格客观。
