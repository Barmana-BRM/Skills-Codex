# 公众号文章骨架、开头与标题

结构服务主题，不是统一模板。先从任务书判断文章要完成什么，再选择骨架。

## 一、七类骨架

### 1. 痛点解法

适合：教程、效率、运营、工具使用、避坑。

```text
具体痛点或失败场景
→ 为什么常见做法失效
→ 核心方法
→ 分步执行与验证
→ 常见错误和适用边界
→ 下一步行动
```

必须补齐：前置条件、完成标准、失败信号。不要只列步骤。

### 2. 故事推进

适合：人物、品牌、项目经历、案例复盘。

```text
真实场景或冲突
→ 选择与代价
→ 关键转折
→ 结果与证据
→ 复盘出的判断
→ 对读者的迁移价值
```

只允许使用用户明确提供或有来源的事件。材料不足时不得补写对白、感官、地点和“朋友”。

### 3. 清单指南

适合：工具合集、准备清单、检查表、资源整理。

```text
选择标准
→ 按场景组织的项目
→ 每项的价值、限制和最佳适用
→ 快速选择路径
→ 不应该选什么
```

不要堆薄条目。每项至少说明“是什么、适合谁、限制是什么”。

### 4. 对比决策

适合：产品、方案、模型、策略对比。

```text
读者决策问题
→ 先定义比较标准
→ 逐维度比较
→ 关键权衡
→ 按场景推荐
→ 哪些情况都不适合
```

先有标准再有结论。使用“更适合……当……”“代价是……”而不是无条件“最好”。

### 5. 热点解读

适合：新闻、政策、发布、行业变化。

```text
发生了什么
→ 已确认事实与时间线
→ 为什么现在发生
→ 对不同人群的实际影响
→ 容易被误读的地方
→ 接下来观察哪些信号
```

热点不等于复述新闻。新增价值来自解释、边界、影响和观察指标。

### 6. 纯观点

适合：行业判断、反常识、认知讨论。

```text
明确命题
→ 常见看法及其不足
→ 证据和推理链
→ 最强反方
→ 命题成立的条件
→ 读者应改变什么判断或行动
```

观点必须可反驳、有边界。不要用情绪替代推理。

### 7. 复盘

适合：项目、增长、内容、产品、活动复盘。

```text
目标与约束
→ 做了什么
→ 结果和证据
→ 哪些有效、哪些无效
→ 原因与反事实
→ 下一轮保留、停止、尝试什么
```

结果一般必须有真实材料。若数据不完整，明确说明观察范围。

## 二、开头钩子

开头的任务是让读者迅速理解“这和我有什么关系”，不是制造戏剧。

可用方式：

- 具体问题：点出读者正在经历的摩擦。
- 可信事实：用已核实的变化或数字建立语境。
- 冲突：两个看似都对的选择发生矛盾。
- 判断：直接提出全文要证明的命题。
- 场景：仅使用真实材料构成一个短场景。
- 结果先行：先说可验证结果，再解释过程。
- 决策点：把文章放进一个明确选择中。

避免：

- “在这个日新月异的时代……”
- “随着科技飞速发展……”
- “你有没有想过……”
- “震惊！所有人都错了……”
- 没有材料却写“昨晚一个朋友问我”。
- 开头三段仍未说明文章要解决什么。

## 三、标题候选矩阵

一次生成 6-10 个候选，机制尽量不同：

| 类型 | 公式 | 约束 |
|---|---|---|
| 直接任务 | 如何/怎样 + 完成具体任务 | 正文必须有可执行方法 |
| 对象+结果 | 谁 + 在什么条件下 + 得到什么 | 不保证不可控结果 |
| 反常识 | 你以为 X，真正决定 Y 的是 Z | 必须有推理或证据 |
| 对比决策 | A 还是 B：按哪些条件选 | 正文先定义标准 |
| 真实数字 | N 个步骤/案例/发现 | 数字必须与正文一致 |
| 新闻影响 | X 发生了什么，对 Y 意味着什么 | 日期和事实需核实 |
| 风险避坑 | 做 X 前，先确认 Y | 风险不能夸大 |
| 观点命题 | 我为什么认为 X | 可写第一人称判断，不虚构亲历 |

选择标题时按顺序检查：

1. 正文能否完全兑现。
2. 读者和对象是否明确。
3. 是否具体到足以区分同题文章。
4. 是否自然、有张力但不夸张。
5. 关键词是否自然出现。

18-28 个中文字符仅是常见编辑区间。必要时可以更长或更短，不为凑长度删掉关键限定。

## 四、小标题

好的小标题应该推进一个问题或判断：

- 差：`为什么重要`
- 好：`真正改变的不是价格，而是团队的试错成本`

- 差：`具体步骤`
- 好：`先固定输入标准，再决定用哪个模型`

小标题不必整齐对仗。章节长度也不必完全相同。信息需要多少就写多少。

## 五、结尾

选择一种结尾：

- 决策结尾：告诉读者下一步先做哪一个选择。
- 行动结尾：给一个当天可以执行的小动作。
- 观察结尾：列出未来判断变化的 2-3 个信号。
- 边界结尾：说明这套方法在哪些条件下不成立。
- 回扣结尾：回到开头冲突，但提供了新的解释。

避免“未来可期”“让我们拭目以待”“希望本文对你有所帮助”等通用收尾。
