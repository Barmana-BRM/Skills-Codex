# UMAT 事务式状态更新与原子提交

## I — 方法论骨架（Interpretation）

1. 把一次可失败的材料更新看成事务：已验收的 `committed` 状态是唯一重试起点，所有新结果先进入 `trial`。
2. 事务状态不只有应力；它包括全部 `STATEV`、累计量、事件标志，以及当前分析真正要求的能量/热耦合输出。
3. 局部积分、回映或损伤演化不得就地污染 committed 快照；每次重试都从同一快照完整重算。
4. 候选态必须同时通过数值条件、物理条件、有限值和接口形状检查，才有资格提交。
5. `STRESS`、`STATEV` 与 `DDSDDE` 应来自同一条已验收更新路径，并作为一个输出包提交。
6. 把 `SSE/SPD/SCD/RPL/DDSDDT/DRPLDE/DRPLDT` 中目标过程实际读取的量也纳入同一输出版本；不要把“非历史数组”误当成可与新状态任意拼接的量。
7. 为事件分别声明 `first/current/latest` 语义；不要用 `KINC==1` 推断材料第一次调用，也不要只存裸 `KINC` 冒充跨 step/restart 的全局事件时间。
8. 失败时丢弃整个 trial 包；不能保留“看起来还对”的某一部分，也不能推进局部时间、累计量、删除或首次事件时序。
9. 本地重试预算耗尽后，恢复 committed 状态，再交给专门的失败升级协议处理，而不是静默返回半更新结果。

## A2 — 触发场景（Future Trigger）★

### 用户会在什么情境下需要这个 skill？

1. 子步、Newton/CPA 或损伤演化失败后，下一次重试结果依赖前一次失败尝试。
2. `STRESS`、`STATEV`、`DDSDDE` 来自不同分支，或只有一部分在早退前被写回。
3. NaN、越界或物理检查失败后，需要证明状态可以恢复到同一已接受起点。
4. 首次屈服/损伤增量、累计塑性量或能量在拒步时被提前记录。
5. 设计嵌套事务：一次 UMAT 调用内含多个可接受/拒绝的局部子步。
6. 多步或 restart 分析中使用 `KINC==1` 初始化，或把 `±KINC` 当作首次/最近事件历史。
7. 应力和历史已回滚，但 `SSE/SPD`、热耦合输出、删除状态或诊断版本仍来自失败 trial。

### 语言信号（用户的话里出现这些就应激活）

- “失败重试后 STATEV 被污染了。”
- “STRESS 更新了但 DDSDDE 还是旧的。”
- “trial state / committed state 怎么分？”
- “rollback material point state / atomic commit”
- “拒步后怎么保证重算等价？”
- “KINC==1 能不能判断第一次调用 / first-event history?”
- “energy outputs / deletion flag 也要 rollback 吗？”

### 与相邻 skill 的区分

- 与 I01“更新器机制路由”的区别：I01 选择物理/数值分支；本 skill 对所有分支规定统一的试算和提交语义。
- 与 I03“PROPS/STATEV 位置契约”的区别：I03 定义每个槽位是什么；本 skill 定义这些槽位何时可被写入或回滚。
- 与 I06“显式自适应子步”的区别：I06 设计误差、调步和接受/拒绝算法；本 skill 抽取可复用于隐式与损伤支路的状态事务底座。
- 与 I08“PNEWDT 失败升级”的区别：本 skill 保证失败返回前状态干净；I08 决定本地预算耗尽后如何请求全局 cutback。

## E — 可执行步骤（Execution）

当 skill 被激活后，agent 应按以下步骤执行：

1. **枚举事务边界和可变状态**
   - 记录目标 Abaqus 版本、分析过程及官方接口对全局 Newton 重调、cutback 和再次调用 UMAT 的状态语义；再分别列出 UMAT 调用级、局部子步级和局部迭代级起点。
   - 建立输出清单：应力、全部 `STATEV`、累计量、事件/删除、`DDSDDE`、适用的能量/热耦合输出、局部时间/路径位置和诊断版本。为每项标注 `input/committed/trial/derived-only` 所有权。
   - 完成标准：每个会被候选计算修改或被宿主读取的量都只属于一个明确状态包，没有隐藏的全局/SAVE 可变状态；能引用目标版本契约说明“本次返回”与“宿主最终接受”的边界。
   - 判停条件：若无法确认某变量是工作量还是跨增量历史，停止实现并先完成 I03 的语义表。

2. **创建 committed 快照与独立 trial 包**
   - 在可重试计算开始前复制 committed；每轮候选只读该快照并写入新的 trial，不就地改写接口数组。
   - 完成标准：连续两次以相同输入启动的 trial 在数值容差内给出同一结果。

3. **完成候选更新而不提前提交**
   - 在 trial 中完成应力、全部历史量、事件/删除状态、能量/热耦合量和候选 Jacobian；首次事件只做候选记录。
   - 将事件契约写成 `first/current/latest` 三选一或并存字段；若需跨步定位，保存足以唯一定位的 `(KSTEP,KINC)`、`TIME` 或单调事件计数，不把裸 `KINC` 当全局时钟。
   - 完成标准：候选包内部的应力、状态、事件、能量和 Jacobian 对应同一阶段点与同一算法路径；任何事件槽都能回答其语义和跨 step 行为。

4. **执行统一验收门**
   - 检查数值残差/误差、物理可容许域、数组长度、有限值、状态范围、事件不变量及必须输出是否全部已赋值。
   - 完成标准：形成逐项布尔验收记录；其中包含“新 step/restart 不重置持久历史”和“拒步不产生 first/latest 事件”两项，只有全部为真才进入提交。
   - 判停条件：任何 NaN/Inf、越界、缺失输出或物理条件失败都直接拒绝，不允许“先提交再修”。

5. **原子提交输出包**
   - 一次性把 trial 的 `STRESS`、`STATEV`、`DDSDDE`、事件/删除及所需能量/热量输出复制到接口；随后才推进局部时间或把 trial 作为下一子步 committed。
   - 完成标准：接口返回量全部带有同一个提交版本号/路径标识，且不存在一新一旧的混合。

6. **拒绝、恢复与升级**
   - 丢弃 trial，恢复 committed，缩小局部步或采用定义好的备选方案重算；不得推进时间、累计量、事件、删除或输出版本。
   - 分别注入局部拒绝、全局 cutback、新 step 首增量和 restart；比较 `STRESS/STATEV/DDSDDE`、能量/热量及事件字段。
   - 完成标准：失败前后 committed 包逐字段相同；改变 step 划分不改变持久历史；作业日志证明宿主按目标版本语义重调，且新调用输入不含被拒 trial 的任何副作用。
   - 判停条件：达到最小步长、最大重试数或不可恢复错误时，保持 committed 并转交 I08 的 `PNEWDT`/cutback 协议，不静默假成功。

## B — 边界（Boundary）★

### 不要在以下情况使用此 skill

- 只需查 `PROPS`/`STATEV` 下标含义而没有候选失败或重试语义时；用 I03。
- 只需选择 α、Δλ 或 e 对应的更新器时；用 I01。
- 想由事务包装掩盖错误本构、错误 Jacobian 或缺失物理模型时；事务只能防污染，不能使候选本身正确。
