# 图标与图形专项检查

用户专门评审图标作品、页面包含成组图标，或初检发现图标系统性问题时使用。重点评审整套规则，不把单枚图标画得精致等同于系统质量。

## 1. 评审顺序

依次判断：

1. 图标的角色和使用层级是否相同。
2. 语义能否快速、稳定地识别。
3. 是否共享风格基因、视觉体量和复杂度。
4. 描边、端点、圆角、角度、透视、正负空间和色彩是否形成规则。
5. 在目标尺寸、背景和交互状态下是否仍然成立。

角色不同可以有不同语言，但要有可解释的层级规则；不要为了形式统一牺牲识别度。

## 2. 统一基因

- 比较线性、面性、线面结合、双色、渐变和立体语言。同一级图标通常只使用一种主语言。
- 选中与未选中使用面性/线性切换可以成立，但整组切换规则、颜色和体量必须一致。
- 检查主描边、内部语义线、端点、连接、断点、标签页、缺口和镂空是否来自同一套 Token。
- 圆角应形成有限层级，而不是要求所有路径使用同一个半径；比较外轮廓、内部结构和线端的关系。
- 正视、侧视、俯视、等距和透视角度不能无理由混用；倾斜方向及深度表达要稳定。
- 箭头、勾选、关闭、展开、跳转等重复符号要保持方向语义和结构一致。
- 多个图标共享母形时，优先复用同一骨架，只改变核心语义符号。

## 3. 光学体量与网格

- 等宽等高不等于视觉等大。比较彩色面积、描边密度、负空间、轮廓复杂度和重心。
- 方形、圆形、三角形、细长形和不对称图形可在共同 Keyline 上做光学超出或缩进。
- 用剪影、灰度和轻微模糊观察整组；仍明显更黑、更宽、更高或更拥挤的图标需要补偿。
- 检查几何中心与视觉中心。播放三角、箭头、带标签页或侧向附件的图标常需光学位移。
- 区分画板、Live Area、可见图形和交互热区；不要把四者混成同一个尺寸。
- 网格用于稳定关系，不是机械限制。先识别当前系统规则，再判断离群值是否有形态或识别理由。

## 4. 复杂度与尺寸变体

- 比较主轮廓数量、内部语义符号、交叉、层叠、狭窄缝隙和装饰细节。
- 同一级图标应有接近的信息预算；一个极简、一个塞满细节会造成系统跳动。
- 在真实目标尺寸检查，不只看作品集放大图。缩小后先丢失的细节应删除、合并或加粗。
- 需要时分别制作小尺寸简化版、标准版和展示版；不要把展示版直接等比缩小。
- 小尺寸优先保留“一个主轮廓 + 一个核心语义”，装饰、层叠、刻度和纹理最后保留。
- 最小负空间、内部线和端点至少要在目标设备与导出倍率下稳定渲染；不给截图虚构统一像素阈值。

## 5. 语义、状态与场景

- 检查图标是否会被误读成相邻概念，例如回收/同步、书本/地图、收起/删除。
- 陌生、多义或高风险图标应配文字、提示或更明确的符号；不能只靠设计师解释。
- 颜色不能成为选中、错误、完成等状态的唯一线索。
- 检查默认、选中、禁用、危险、加载等适用状态是否共享同一转换逻辑。
- 图标可见尺寸可以小于操作区域；热区按目标平台和产品规范检查，不套单一尺寸。
- 检查图标与文字的基线、间距和共同视觉重量，而不是只做几何垂直居中。

## 6. 色彩、材质与插画

- 先确认颜色承担品牌、分类还是状态语义；同一颜色不要无理由承担冲突角色。
- 比较不同色相的感知明度、饱和度和面积；相同数值不等于相同视觉响度。
- 渐变、高光、阴影、描边透明度和光源方向要形成共同材质规则。
- 彩色图标与单色图标可以并存，但必须对应明确层级、状态或场景。
- 插画与功能图标同时出现时，检查轮廓、圆角、色调、透视和材质是否属于同一品牌语言；角色不同则分库管理。
- 关键功能图形需在实际背景上复核非文字对比；装饰图形不机械套用功能图形标准。

## 7. 矢量与导出质量

- 检查路径是否出现多余锚点、尖角、断裂、重叠、反向填充或不必要的布尔复杂度。
- 检查描边对齐、缩放方式和最终尺寸下的像素落点，避免半像素或非整数缩放导致发虚。
- 比较相同资源的画板、内边距、命名和导出倍率是否一致。
- 检查浅色、深色、单色、反白和高对比背景；不要只在作品集背景上验收。
- Figma 有元数据时检查是否复用同一组件、变量和母形；截图只能判断可见结果。

## 8. 验证与修复顺序

验证：

1. 100% 实际尺寸。
2. 去色剪影。
3. 轻微模糊。
4. 浅色与深色背景。
5. 关键状态并排。
6. 与真实文字和组件一起使用。

修复顺序：

1. 先明确角色、语义和状态规则。
2. 再统一母形、视觉体量和复杂度。
3. 然后统一描边、端点、圆角、角度、透视和正负空间。
4. 最后调整颜色、渐变、阴影和装饰细节。

不要只把所有图标设为相同宽高，也不要只统一线宽后就宣称系统完成。
