## 1. 总体判断

先回答三个问题：

1. 用户第一眼看见什么？它是否等于当前页面最重要的信息或操作？
2. 页面气质是否符合产品、场景和用户，而不只是“好看”？
3. 视觉差异是否在表达层级，还是仅仅制造噪声？

区分三类问题：

- **正确性**：对齐、遮挡、模糊、状态误导、不可读等明确错误。
- **一致性**：相同语义却使用不同视觉语言，或不同语义看起来完全一样。
- **表现力**：层级、节奏、品牌、质感不够清晰；它依赖上下文，不能套固定风格。

## 2. 形

检查图标、按钮、卡片、容器、插图和基础几何形态。

### 图标

- 先检查语义、角色、视觉体量、统一基因和实际尺寸识别度，再检查线宽、圆角等局部参数。
- 线性/面性切换只有在对应稳定的状态或层级规则时才成立，不能随机混排。
- 陌生、多义或高风险图标应配标签、提示或更明确的图形。
- 图标成组出现或用户专门评审图标作品时，使用 [icon-quality.md](icon-quality.md) 做完整专项检查。

### 控件与容器

- 比较相同角色按钮的高度、圆角、边框、图标尺寸、内边距和文字位置。
- 检查主次按钮差异是否足够，并避免把普通状态画成禁用、危险或已选中。
- 检查圆角体系是否有逻辑：外层容器圆角通常不应小于贴近边缘的内层圆角；嵌套圆角需考虑内边距带来的视觉关系。
- 检查形态是否与语义相符。切换、单选、复选、标签、按钮和输入框不应仅因视觉偏好而互相伪装。
- 检查可点击区域与可见图形是否混为一谈；图标可以小，但操作热区要足够。

### 判断提示

- 模糊观察一组图标或控件；若某个仍明显更黑、更大或更拥挤，通常存在视觉重量问题。
- 临时转为灰度；若形态层级消失，说明设计过度依赖色相。
- 缩小到实际使用尺寸；若轮廓或状态难分辨，优先简化结构。

## 3. 色

从色相、明度、饱和度、面积、语义和环境六方面检查。

### 色彩角色

- 识别品牌色、强调色、功能色、中性色、背景层和文字层；同一颜色不应在不同页面承担冲突语义。
- 检查主色是否真正支持主任务，而不是平均散落在每个区域。
- 检查成功、警告、错误、信息等功能色是否稳定，并配合文字或图形，不能只靠颜色传意。
- 检查中性色是否与主色气质协调；中性色可轻微带品牌色倾向，但不能损害可读性。

### 明度与饱和度

- 优先用明度差建立可读层级，再判断色相和饱和度。
- 高饱和色面积越大，视觉压力通常越强；把它用于焦点时要控制面积和数量。
- 多个高饱和颜色同时争抢注意力，通常会破坏单一主焦点。
- 高饱和互补色大面积紧邻时，检查边界是否产生色振动；只有影响阅读、识别或视觉稳定时才报告。
- 颜色看似同属一套但感官明度跳跃时，检查不同色相造成的感知差异。
- 深色界面中注意高饱和色的炫光感、纯白文字的刺激感和灰阶层级不足。

### 对比与可访问性

- 普通文字与背景至少检查 4.5:1；大号文字至少检查 3:1。
- 关键控件轮廓、状态指示和信息图形检查非文字对比。
- 不以“低对比更高级”为由牺牲正文、占位符、辅助信息和禁用以外状态的可读性。
- 图片上的文字要检查图片最亮和最暗区域，必要时增加遮罩、文字底板或改变裁切位置。
- 户外强光、低亮度屏幕或远距离阅读场景需要预留更充足的可读性余量，但不要把场景建议误写成通用合规阈值。

### 色彩一致性

- 检查近似但不相同的颜色是否有明确角色；无意义的 `#333/#343434/#363636` 漂移会增加系统噪声。
- 检查相同状态在不同组件中的颜色是否一致。
- 检查插图、照片、图标和 UI 主色的色调是否冲突。

## 4. 字

检查字体家族、字号、字重、行高、字间距、颜色、对齐、宽度、语言和内容增长。

### 层级

- 建立清晰但克制的文字层级。不要只靠字号；组合字重、颜色、间距和位置。
- 相邻层级差异过小时，用户难以判断主次；差异过多会让页面碎片化。
- 同一语义角色应复用相同样式，除非场景确实需要变化。
- 标题、正文、辅助、标签、数值和按钮文字应有可解释的角色，不要出现大量一次性样式。

### 中文与混排

- 中文笔画密度高，过细字重在小字号和低对比下容易发虚。
- 中文字体的名义字重差异在小字号下未必形成足够视觉差异；必须在目标字体、设备和真实渲染尺寸验证。
- 中文、英文、数字和单位的视觉大小并不天然一致；检查基线、字面高度与间距，而不是只看相同字号。
- 价格、百分比、日期和表格数值检查数字对齐；需要纵向比较时优先考虑等宽数字。
- 中英文标点、空格、大小写和单位写法保持一致。
- 英文全大写或高密度数字样式需要检查字间距和整体词形，不直接沿用正文参数。

### 阅读性

- 正文行高需要给笔画和换行足够呼吸空间；不要把某个固定倍数当作所有字号和场景的硬规则。
- 奇数或偶数字号本身不是质量结论；检查字阶角色、平台渲染、基线和层级是否稳定。
- 文本行过长会降低回行效率；过窄会导致频繁换行。根据设备、字号和内容调整。
- 大段居中、两端对齐或全大写会降低连续阅读效率，除非文本很短且有明确视觉目的。
- 检查文本与容器边缘、图标、图片圆角之间的光学距离，不盲从机械对齐。

### 内容增长

- 用真实长度检查标题、姓名、金额、日期、按钮、标签和多语言文案。
- 检查两行/三行、超长英文、无空格字符串、动态字号和系统放大。
- 截断必须有理由，并提供查看完整内容的方式；核心信息不应依赖悬停才能读取。

## 5. 质

“质”指图片、插图、渐变、投影、材质、描边、模糊、噪点和资源完成度。

### 图片与插图

- 检查分辨率、裁切、主体位置、色温、曝光、饱和度和风格是否协调。
- 同组配图应有一致的裁切逻辑、调色倾向和视觉重量。
- 避免用低质量占位图支撑最终视觉判断；若仍为占位阶段，在报告中标注。
- 检查头像、商品图和封面图在圆形/圆角裁切后是否截掉主体。
- 检查图片是否被非等比拉伸；图片上的文字和控件要覆盖不同裁切、明暗区域及换图后的最差情况。

### 投影、层级与光源

- 阴影首先表达层级或交互状态，其次才是装饰。
- 检查光源方向、偏移、扩散、模糊、透明度和颜色是否统一。
- 近距离悬浮通常边缘更清晰、范围更小；距离更远通常更柔、更扩散。不要把规律写成绝对公式。
- 避免每个卡片都使用同样强的阴影，导致页面发灰、发脏和层级失效。
- 在深色背景上，单靠黑色投影可能不可见；结合边框、亮部或背景层差表达层级。

### 渐变、玻璃与模糊

- 渐变要有目的：引导视线、表达光照、品牌或空间，不只是填满背景。
- 检查渐变过渡是否浑浊、出现脏色、条带或文字低对比区。
- 玻璃和模糊效果要保证内容层与控制层仍清晰分离。
- 检查高光、折射、阴影和背景光源是否逻辑一致。
- 流行材质不能覆盖可读性、平台可用性和品牌匹配。

### 细节完成度

- 检查 1px 边、矢量路径、导出倍率和缩放后是否发虚。
- 检查遮罩、圆角、描边、投影是否在边缘出现断裂、溢出或锯齿。
- 检查相同资源是否有不一致压缩、清晰度或滤镜。

## 6. 构

检查构图、栅格、对齐、间距、分组、层级、节奏、密度和适配。

### 焦点与层级

- 一个屏幕可以有多个层级，但当前任务通常应有一个主要焦点。
- 所有元素都强调等于没有强调；可通过弱化次要元素而非继续放大主要元素建立对比。
- 检查标题、主信息、主操作是否形成可预测的扫描路径。
- 检查视觉顺序是否与任务顺序一致。

### 对齐

- 识别页面主要对齐线；无理由的 2–6px 漂移会让界面显得松散。
- 机械左对齐不是唯一正确答案。圆角图片、非对称图标和不同字面可能需要光学补偿。
- 并列模块检查顶部、基线、底部和内容起点；选择与阅读关系最强的一条进行对齐。

### 间距与分组

- 先检查“组内 < 组间 < 区块间”的关系是否清晰，再检查具体数值。
- 识别当前设计的间距序列；不在序列中的离群值要确认是否有语义理由。
- 相关内容靠近，不相关内容拉开。分割线、底色和卡片只在空间不足以表达关系时增加。
- 容器内边距应与内容密度和控件尺寸协调；上下左右不必机械相等，但要有结构理由。
- 留白是组织信息和分配注意力的工具，不等同于把页面做空。

### 节奏与密度

- 检查重复模块的节拍：卡片高度、标题位置、图片比例、行数和操作区是否稳定。
- 同一页面出现过多不同容器结构，会增加结构复杂度；能用同构模块表达时优先统一。
- B 端高密度不等于拥挤；通过稳定栅格、明确分组和可扫描对齐提升效率。
- C 端轻盈不等于稀疏；核心信息仍需足够靠近并形成任务闭环。

### 响应式与安全区

- 检查窄屏、横屏、窗口缩放、系统栏、安全区、键盘弹出和底部手势区。
- 避免把关键操作固定在易被系统区域遮挡的位置。
- 检查内容变长后栅格、卡片和按钮是否能伸缩，而不是只适配理想样例。

## 7. 常见根因与改法

### “页面不高级”

优先排查：

1. 主次差异不清，所有内容争抢注意力。
2. 间距没有序列，模块关系含糊。
3. 图标、圆角、字体和颜色来自不同语言。
4. 低对比被误当成克制。
5. 投影、渐变和装饰过多，缺少统一光源和目的。
6. 配图质量或裁切拖累整体。

改法：先统一结构和系统，再精修装饰；先减少无效差异，再增加有意义的表现。

### “页面太平”

不要立即增加阴影和颜色。依次尝试：

1. 拉开信息层级。
2. 调整组内/组间距离。
3. 强化一个主焦点，弱化其他元素。
4. 增加图片比例、尺度或形态对比。
5. 最后才增加材质和装饰。

### “页面太乱”

依次检查：

1. 合并重复或低价值信息。
2. 减少文字样式、颜色角色和容器类型。
3. 重建对齐线与间距序列。
4. 合并重复卡片、分割线和背景层。
5. 统一图标和图片语言。

### “图标不统一”

先统一网格、视觉体量和复杂度，再统一线宽、端点、圆角、角度、透视、正负空间和颜色。不要只把所有图标设成相同宽高。
