## 1. 任务与流程

- 识别页面的核心任务、起点、完成条件和主要阻力。
- 检查视觉主操作是否等于业务主操作；次要操作不能抢走注意力。
- 检查步骤数量、重复输入、无意义跳转和不必要确认。
- 对复杂任务检查是否分步、分组或渐进披露；不要一次暴露全部复杂度。
- 对不可恢复、高风险、付费、发布、删除等操作检查确认、结果预览或撤销机制。
- 检查新手与熟练用户是否都能完成任务；快捷操作不能破坏可发现性。

## 2. 可发现性与语义

- 控件外观应说明它能否点击、当前状态和可能结果。
- 图标、标签、位置和平台惯例共同表达语义；陌生图标不要独立承担关键操作。
- 主按钮文案优先描述动作和对象，避免模糊的“确定”“完成”。
- 链接、按钮、标签、选择器、开关、复选框和单选框应保持各自语义。
- 隐藏手势、长按、滑动和悬停功能需要可发现线索或等效入口。
- 检查命中区域与视觉区域；避免小图标紧密排列造成误触。

## 3. 状态与反馈

对可交互组件检查适用状态：

- default
- hover（桌面/Web）
- focus（键盘）
- pressed
- selected
- disabled
- loading
- success
- warning
- error
- empty
- offline/timeout

每次操作需要及时、与动作相关的反馈。长任务应说明正在发生什么，必要时允许取消或离开。不要用颜色变化作为唯一状态信号。

检查：

- 加载状态是否保留页面结构，避免布局跳动。
- 空状态是否解释原因并提供下一步。
- 错误是否说明发生了什么、影响什么、如何恢复。
- 成功反馈是否足够但不过度打断。
- 已选中、已完成和禁用是否可区分。
- 系统状态变化是否出现在用户注意范围内。

## 4. 表单与错误

- 标签应持久可见；placeholder 不能替代字段标签。
- 必填、选填、格式、单位和示例要在需要时说明。
- 按认知顺序排列字段；相关字段分组。
- 在输入附近显示错误，保留用户已输入内容。
- 错误文案说明原因和修复动作，不只写“出错了”。
- 输入限制尽量预防错误；格式化不应妨碍复制、粘贴或编辑。
- 主操作在不可用时，要让用户理解缺少什么；避免无解释的灰色按钮。
- 检查键盘类型、自动填充、密码显示、验证码和无障碍认证场景。

## 5. 导航与信息架构

- 用户应知道自己在哪里、能去哪里、如何返回。
- 导航层级、名称、顺序和选中态跨页面保持一致。
- 高频和高价值入口不应被无理由藏入更多菜单。
- 面包屑、标签页、分段控件和侧边栏要与信息层级匹配。
- 标签页应切换同一层级内容，不伪装成流程步骤。
- 返回、关闭、取消和完成的行为要可预测。
- 深层页面应保留足够上下文，避免用户失去方向。

## 6. 内容与微文案

- 文案应帮助用户做决定和采取行动，而不是只描述界面。
- 标签优先用用户语言，避免组织内部术语。
- 相同动作使用相同词，不要在“保存/提交/完成”之间无理由切换。
- 错误、支付、权限和隐私场景要准确、克制并提供恢复路径。
- 空状态与新手引导聚焦下一步，不堆砌品牌口号。
- 重要限制和结果不要放在操作之后才说明。
- 截图中的文案若明显是占位内容，只评审层级和容器适配，不批评内容真实性。

## 7. 无障碍硬检查

### 对比

- 普通文本至少 4.5:1。
- 大号文本至少 3:1。
- 关键控件边界、图形和状态指示通常至少检查 3:1 非文字对比。
- 禁用状态可能适用例外，但仍应能被理解为禁用。
- 非文字对比只约束理解内容或识别控件/状态所必需的视觉信息；装饰图形不机械套用。
- Logo 或 logotype 本身可能适用对比例外，但相邻品牌文案、交互边界、焦点状态和承担功能的图形仍需按相应标准检查；不要把所有品牌相关内容一并豁免。
- 不使用颜色作为唯一的信息、状态或错误提示。

拿到准确色值时使用 `scripts/contrast.py`，不要凭肉眼声称精确比率。

### 目标尺寸

- Web 按 WCAG 2.2 检查至少 24×24 CSS px，或满足目标间距/等效入口例外。
- iOS/iPadOS 常用控件参考 44×44 pt 触控区域。
- 视觉图形可以小于热区；报告中区分“图标尺寸”和“可点击区域”。

### 键盘与焦点

- Web/桌面端检查逻辑焦点顺序、可见焦点、跳过重复导航和无键盘陷阱。
- 焦点样式要与背景和未聚焦状态有足够差异。
- 不把 hover 作为唯一访问方式。

### 缩放、重排和动态字体

- Web 文本放大到 200% 不应丢失内容或功能。
- 窄屏/高倍缩放时，除确需二维布局的内容外，避免同时横向和纵向滚动。
- 支持系统动态字体时，检查文本容器能否增高、换行和重排。
- 不以固定高度裁掉正文、按钮标签或错误信息。

### 运动与感知

- 不用快速闪烁、强烈视差或自动重复运动表达必要信息。
- 为减少动态效果的用户提供更温和替代。
- 图片、图表和图标的关键信息要有文字或可感知替代。
- 音频、颜色、形状、位置中的任一单一通道都不应成为唯一线索。

## 8. 证据限制

- 静态截图不能证明 hover、focus、键盘、读屏、动效、响应式和真实热区。
- Figma 原型能展示部分流程，但不能证明实现层无障碍语义。
- 未看到的状态写入“待确认项”，不要直接定为缺失。
- 交互结论依赖业务目标时，明确写出假设和可能的替代解释。
