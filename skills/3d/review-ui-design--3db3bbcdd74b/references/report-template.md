# 评审报告模板

使用以下结构，并根据证据裁剪内容。不要为了完整而编造问题。

## 设计评审结论

- **总体判断**：用 2–4 句说明设计当前最强的地方、最大瓶颈和优化方向。
- **评审范围**：页面/节点/流程。
- **关键假设**：平台、用户、任务或设计阶段；没有则省略。
- **证据限制**：截图缩放、缺少状态、无设计规范等。
- **证据摘要**：列出使用的 Figma 属性、用户规范、计算工具、截图裁切/参考线/近似取色等；没有程序化检查则省略。

## 值得保留

列出有证据的具体优势，并说明为什么有效；通常 2–4 项，但不要为了数量凑优点，也不要写泛泛的“整体不错”。

## 最优先修改

最多列出 3 项真正值得先改的根因；不足 3 项就少列。

1. **[P0/P1] 根因式标题** — 一句话影响 + 一句话行动。
2. **[P0/P1] 根因式标题** — 一句话影响 + 一句话行动。
3. **[P1/P2] 根因式标题** — 一句话影响 + 一句话行动。

## 可视化评审图

- **问题标注图**：直接展示原稿标注图；使用 `V1 / I1 / S1 / A1` 等编号对应下方报告。
- **优化建议图**：直接展示调整方向、对齐关系、尺寸变化或局部前后对比；明确标注“方向示意”。
- 多屏或问题较多时按页面拆图，并在图片标题中写明页面名称。
- 无法可靠生成时说明具体原因，不用失真图片代替。

## 问题与详细建议

按以下三个部分输出：

### 一、视觉质量

覆盖“形、色、字、质、构”。只列有证据的问题。

### 二、交互体验

覆盖任务、可发现性、控件语义、状态、反馈、文案和无障碍。静态稿无法确认的内容放到待确认项。

### 三、设计系统

覆盖 Token、组件、状态、跨屏模式和 Figma 文件健康度。单张截图证据不足时，明确说明。

每条问题使用：

#### [V1 · P1] 问题标题

- **标签**：视觉·构 / 交互·反馈 / 系统·组件 / 无障碍·对比
- **置信度**：已确认 / 高置信 / 待复核
- **证据**：Figma 属性 / 用户规范 / 计算结果 / 截图近似 / 跨屏对照；精确数值注明测量方法。
- **图中标记**：对应问题标注图和优化建议图中的同编号位置；无法视觉化时写“不适用”及原因。
- **位置**：用可定位描述；Figma 可补充节点名或 node ID。
- **现象**：客观描述当前设计，不使用“丑”“不高级”等空泛词。
- **影响**：说明对理解、操作、品牌、一致性或精致度的影响。
- **修改建议**：
  1. 先给最小成本、最高收益的改法。
  2. 再给结构性或系统性改法。
  3. 有依据时提供数值；否则给相对关系、范围或测量方法。
- **验证方法**：说明修改后如何检查是否真的改善。

若同一问题出现多处，增加：

- **影响范围**：列出受影响页面、组件或位置。
- **系统修复**：指出应修改 Token、主组件还是页面实例。

## 30 分钟快速优化

仅在确有低风险、小成本动作时列出，通常不超过 6 项，并按执行顺序排列。没有合适动作则省略；不要把需要重构的事情放进来。

## 修改稿复评模式

用户提交第二轮或后续修改稿时，用增量结构替代完整首轮报告：

| 原编号 | 状态 | 复核结论 | 证据或剩余动作 |
|---|---|---|---|
| V1 | 已解决 / 部分解决 / 未解决 | 说明变化 | 对比位置、测量或下一步 |

- 旧问题保留原编号；新问题续号。
- 上一轮报告或编号不可见时先请用户补充；无法取得则说明限制，并把本轮建立为新基线。
- 修改引入的问题标记为“新增”，已解决后再次出现的标记为“回归”。
- 简要列出本轮保留的优势与是否出现副作用。
- 用户质疑或证据变化导致原判断不成立时，明确记录“结论修正”和置信度变化。
- 复评在可可靠生成时更新一张状态标注图并使用相同编号；无法生成时说明原因。只有仍存在或新增问题需要新的视觉方向时才更新优化建议图。

## 待确认项

仅列当前材料不能确认、但值得下一轮检查的内容，例如：

- hover/focus/pressed/disabled/loading/error/empty 状态
- 实际热区和键盘焦点
- 动态字体与多语言
- 响应式和横竖屏
- Figma Token/组件复用

## 输出质量检查

- 是否把最重要的问题放在前面？
- 是否保留了设计已有优势？
- 是否解释了每条建议的原因和预期结果？
- 是否把重复问题合并成根因？
- 是否避免截图下的虚假精确数值？
- 是否区分严重度和置信度？
- 是否说明精确判断的证据来源和测量方法？
- 首评是否交付问题标注图和优化建议图，或说明无法生成的原因？
- 复评是否按需更新状态标注图与优化建议图，或说明无法生成的原因？
- 图中编号是否与报告条目一一对应？
- 复评时是否保留旧编号并区分解决状态、新增和回归？
