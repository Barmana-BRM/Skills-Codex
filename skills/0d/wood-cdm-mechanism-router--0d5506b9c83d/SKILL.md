# 木材本构机制路由器

## I — 方法论骨架

1. 从需要解释或预测的可观测现象出发，不从某个判据名称出发。
2. 在 L/R/T 材料轴内区分载荷符号、应力路径、永久应变、刚度下降和裂纹拓扑。
3. 弹性负责可恢复响应；塑性负责不可恢复应变与硬化；损伤负责承载或刚度的不可逆退化。
4. 损伤起始只回答何时及哪一模式触发，不能代替塑性积分、峰后演化或删除规则。
5. 完全分离、裂纹闭合、摩擦接触或显式拓扑变化需要评估内聚、XFEM、相场或连续—离散方案。
6. 耦合模型先做机制隔离基准，再做多机制竞争和应力重分配验证。
7. 最终交付是一张“现象—机制—状态—算法—证据”责任表，不是一个模型名称。

## A2 — 触发与路由

在以下场景调用：

- 一个木材 UMAT 同时包含压缩压溃、拉伸开裂、滚动剪切、残余应变或元素删除，但各公式职责不清。
- 准备用 Hill48 替换 J2，或让一个 Tsai-Wu/failure index 同时承担屈服、损伤和删除。
- 结构试验同时出现塑性平台与脆性裂纹，需要在 CDM、塑性、内聚、XFEM 或相场之间分工。
- 模型能运行，却无法解释卸载残余、模式归因或某分支是否实际激活。

若机制已经冻结，只剩局部回映、硬化插值或切线推导，转专用积分器或 `ddsdde-finite-difference-audit`。若只是位置 ABI 或 Voigt 映射，转 `umat-props-statev-contract` 或 `abaqus-tensor-voigt-adapter`。

## 输入与输出合同

必需输入：

- 目标量：峰值、残余应变、卸载刚度、损伤带、裂纹路径、完全分离或接触中的至少一项。
- L/R/T 材料轴、拉压符号、剪切面、单调/循环与应力路径。
- 至少一种局部或路径证据，例如卸载曲线、DIC、裂纹模式、断裂能或残余变形。
- 求解器、可否增加自由度以及验证预算。

输出：

- `现象 -> 机制 -> 起始/屈服条件 -> 演化/积分器 -> 历史变量 -> 验证证据` 责任表。
- 被拒绝的机制与证据不足项。
- 机制隔离基准和后续 skill 路由。
- `ROUTED`、`ROUTED_WITH_ASSUMPTIONS` 或 `BLOCKED_BY_EVIDENCE`。

## E — 执行步骤

1. 将目标改写成可证伪命题，并为每个命题定义可观测输出和验收尺度。
2. 建立材料轴—载荷—现象表；材料轴未知且会改变起裂位置时，先用 `wood-fiber-orientation-field-pipeline`。
3. 分配机制角色，确保同一物理量没有两个未声明优先级的写入者。
4. 分别列出屈服、流动/回映、损伤起始、损伤演化、刚度合成和删除条件。
5. 检查连续损伤是否能回答目标；真实裂面、闭合或接触不得用元素删除冒充。
6. 设计压缩—卸载塑性基准、拉伸/剪切损伤基准和一个多机制结构基准。
7. 输出责任表、假设、未解决项和下一步 skill。

## B — 边界

- 纯刚度损伤通常不能独立表示永久塑性变形。
- Hill48 是塑性语言，不自动提供损伤演化。
- Tsai-Wu、Hashin 或其他失效指标不是塑性残差，也不是完整损伤更新器。
- 元素删除是拓扑近似，不等于裂面、闭合和摩擦已建模。
- 木材中常见的“压缩塑性、拉/剪损伤”只是路由起点，必须用当前树种、含水率和路径证据验证。
