# SP 站内外流量诊断

## 先取这些资料

目标广告账户、站点、活动和 ASIN；当前 site 选项截图/导出；同期可用站点、广告位、媒体或渠道报告；每日曝光、点击、花费、订单、销售额；归因窗口与数据成熟日；价格、库存、Featured Offer、优惠和主要变更日志。

## 工作流

1. 按 [官方基线](references/official-baseline.md) 核对账户实际具备的投放范围、报告维度和控制项。site 选择与 placement 加价不是同一设置；不要虚构独立的“创作者开关”。
2. 读取 [数据契约](references/report-contract.md)。先分开站内站外，再区分媒体与创作者；若报告没有该层细分，明确 UNAVAILABLE，不能靠猜测拆分。
3. 把同一期间、币种、归因范围的渠道小计与活动合计对账。只在分区互斥且完整时计算剩余项；不可把“总数减站内”自动命名为创作者流量。
4. 逐渠道重算 CTR、CPC、订单/点击、ACOS 和花费占比，并展示绝对量。变化拆成需求、流量构成、点击成本、转化及可售状态，保留多种解释。
5. 观察期与基准期采用相同长度、成熟度和范围。记录活动选项变化与渠道放量时间，但时间吻合只构成相关线索。零销售时 ACOS 为不可计算，不记为零。
6. 提出保留、继续观察、核查商品/素材或受控投放比较。先看当前控制台是否允许原活动修改 site；若不可改，说明需要新建试验活动及预算，不伪造直接切换能力。
7. 如用户授权覆盖具体活动、设置和预算，保存旧值后执行并回读；只有未覆盖的动作才补授权。禁止为了“修复”批量关闭所有站外流量。

## 交付

范围及可见性矩阵、总分对账、前后绝对量和比率、竞争解释、最小实验、停止/回退条件及实际验证层级。无渠道证据时给 HOLD 和最小补数清单。

执行与实验检查见 [playbook](references/playbook.md)。
