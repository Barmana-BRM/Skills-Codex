# UMAT 从原子模块到边值问题的分层验证矩阵

## I — 方法论骨架 (Interpretation)

UMAT 验证不是一次“跑通”判断，而是逐层增加复杂度、逐层隔离错误来源的证据链。
先把每个待证结论拆成命题，再为该命题记录来源路径、SHA-256、证据角色、独立来源族、可支持/不可支持范围、阈值和结果；不要给整份文件贴一个笼统“高等级”。
用 SHA 判定字节身份：同 SHA 的多个路径保留全部出处但只计一个实现；不同 SHA 只证明字节不同，不自动证明方法新颖、正确、独立或可再分发。
把证据角色分开：`fixture` 是受控输入，`run trace` 是完成/中止日志，`observation` 是 ODB/云图/曲线，`quantitative result` 才是带真值、误差和阈值的验收结果。
最底层验证固定数学算子、张量表示、导数和接口尺寸；这些失败时不应进入求解器。
材料点层用解析极限或独立实现重放规定路径，检查应力与全部历史量，而不是只看终值。
单元体层再引入 Abaqus 接口、Voigt/工程剪切、`PROPS/STATEV`、单元类型和边界约束。
随后用多轴、卸载反向、步长切分、状态提交和 `DDSDDE` 扰动检验离散更新及全局 Newton 行为。
只有前述门通过，才用有量化基准的边值问题检查网格、边界条件和系统级耦合。
每一层预先声明待证主张、独立参考、输入同一性、阈值和失败回退；后一层的彩色云图不能替前一层补证。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 准备把新 UMAT 用于论文、工程计算、参数反演或生产分析，需要制定验收门。
2. 作业能完成、曲线“差不多”或云图看起来合理，但没有独立基准和自动阈值。
3. 找不到 Abaqus 内置对应材料模型，不知道怎样建立独立参考。
4. 不确定单积分点、单元体、步长敏感性、切线审计和边值问题应按什么顺序执行。
5. 一个高层算例失败，需要判断是算子、本构路径、接口、Jacobian 还是边界条件导致。
6. 完整接触模型只有少数积分点异常，需要先用关闭接触、单元体和材料点复现决定是否进入语义调试。
7. 同名或多路径源码需要判断是否独立证据，或报告把 OBJ/CAE/HM/INP/JNL/ODB 混成一个“来源数量”。
8. 需要说明“byte-new”“作业完成”“云图相似”分别能证明和不能证明什么。

### 语言信号 (用户的话里出现这些就应激活)

- “这个 UMAT 怎么验证 / validate my UMAT”
- “帮我设计 verification matrix / benchmark suite”
- “没有内置模型怎么做 reference solution？”
- “云图对了是不是就算验证通过？”
- “Job Completed/Aborted 说明什么？”
- “same SHA counts as two sources / provenance deduplication”
- “INP fixture、JOB log、ODB cloud plot 哪个算 validation evidence？”

### 与相邻 skill 的区分

- 与 `umat-semantic-debugging` 的区别：故障层未知时本 skill 先分流；最小单元或受限日志一旦证明 UMAT 数据流先偏离，就条件转交后者追踪第一个语义断点。若根因在接触/边界，则不调用语义调试。
- 与 `ddsdde-finite-difference-audit` 的区别：后者是本验证矩阵中的 Jacobian 专项门，不覆盖模型物理与边值问题。
- 与 `cpa-implicit-return-mapping` 的区别：后者构造一次塑性更新；本 skill 判断该更新从算子到系统级是否有足够证据。

## E — 可执行步骤 (Execution)

1. **建立主张—证据矩阵**
   - 为公式、导数、表示、状态演化、增量映射、切线、收敛和工程响应分别建立 `claim_id`；禁止用“验证这份文件”代替命题。
   - 为每条证据记录规范路径、SHA-256、来源类别（直接/补充/派生/构建）、角色（source/fixture/run-trace/observation/quant-result）、独立来源族、可支持/不可支持命题、输入输出、单位、阈值和结果。
   - 对相同 SHA 合并证据权重但保留所有路径；对不同 SHA 只登记字节身份不同，另查方法来源、实现独立性和许可证，不把 byte-new 当 novel/correct。
   - 记录目标 Abaqus 版本、单元族、应变假设和适用材料域，避免把一个算例的结论外推。
   - 完成标准：每个结论可回指一个 `claim_id` 和至少一个未超界的证据项；重复副本计数为一，且不存在“看起来合理”“来源有三份”这一验收项。

2. **通过 L0 原子算子门**
   - 单独测试弹性矩阵、应力不变量、`F/G`、解析导数、张量/Voigt 往返、材料坐标和数组长度守卫。
   - 使用手算、符号/自动微分、解析极限或不同实现交叉核对，并覆盖零态、纯法向、纯剪和边界极限。
   - 完成标准：所有算子在预设阈值内通过；任一失败则停止，不进入 UMAT 集成。

3. **通过 L1 材料点路径门**
   - 用独立高精度积分或解析解重放弹性、首次屈服、持续塑性/损伤、卸载、反向、多轴和边界路径；比较完整应力与每个历史变量的全过程。
   - 改变材料点步长并检查残差、事件时刻和耗散/能量（若模型定义）；参考实现不得复制同一核心代码。
   - 完成标准：所有路径的历史曲线、事件顺序和终值均达到事先设定的尺度化阈值。
   - 失败路径：先回到发生首个偏差的算子或更新阶段；若证据显示 UMAT 变量数据流先偏离，转交 `umat-semantic-debugging`，不用边值模型继续“调参”。

4. **通过 L2 Abaqus 单元体接口门**
   - 让单积分点/单单元复现 L1 的同一路径，核对 `NDI/NSHR/NTENS`、工程剪切、方向、`PROPS/STATEV/SDV`、初始化和提交语义。
   - 若有内置模型，几何、载荷、步、网格、单元、参数和输出保持一致，只替换材料实现；无内置模型则对照 L1 独立参考。
   - 把未运行的 INP 明确标为 fixture；只有保存作业状态、逐积分点历史和量化误差后才升级证据角色。
   - 完成标准：接口级结果与 L1 相符，拒步/重试不污染历史，且每个 SDV 的含义可由映射表解释；账本不把 fixture 计成 pass。

5. **通过 L3 离散与求解器门**
   - 做多档全局增量切分、加载路径、卸载重载和必要的纯旋转/维数测试；用 `ddsdde-finite-difference-audit` 检查光滑区完整映射导数。
   - 记录局部迭代、全局 Newton 次数、cutback、失败原因和结果随步长的收敛趋势。
   - 完成标准：响应趋于稳定，切线达到声明等级，局部与全局收敛证据分开记录；否则回到 L1/L2 或切线专项门。

6. **通过 L4 边值问题门**
   - 选择有解析解、公开基准、独立实验或已知定量趋势的系统算例；先做网格/边界/单元敏感性，再比较载荷—位移、场量、事件和能量。
   - 确认目标载荷与时间真正完成，并把稳定化、初态和参数与参考保持一致；把 `JOB_COMPLETED/ABORTED` 记录为 run trace，把 ODB/云图记录为 observation。
   - 为云图对应的量名、单位、积分点/节点位置、帧、反力集合和颜色范围建立可复查数值导出，不以视觉相似代替误差。
   - 完成标准：作业正常完成，关键量在预设阈值内匹配，且结论不由单一网格、步长或稳定化开关主导；Aborted 最后一帧只进入诊断栏，不进入 pass 栏。

7. **签署限域结论与回归集**
   - 逐层记录通过/失败、数据、阈值、已验证域和未验证域；将最小案例固定为后续代码变更的回归集，并保存输入/结果的 SHA 与生成版本。
   - 完成标准：报告能回答“每个命题由哪份独立证据证明、什么只是一份夹具/运行痕迹/观察、没证明什么、失败应回到哪一层”，并禁止用高层云图覆盖低层失败。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 只需定位一个编译错误、漏赋或错误实参：先用语义调试技能建立最小复现。
- 只需检查 `DDSDDE` 一项：使用有限差分专项审计，再把结果纳入本矩阵。
- 没有明确模型主张、参数来源或适用域，却希望验证框架替代材料标定。

## 相关 skills

- **depends-on**: 无——它是为任一本构更新器组织独立证据链的通用验收框架。
- **contrasts-with**: 无——调试定位与修复后验证是先后组合，不是二选一方案。
- **composes-with**: `ddsdde-finite-difference-audit`、`umat-semantic-debugging`——把切线专项结果纳入证据链，并在语义偏差修复后执行独立验证。
