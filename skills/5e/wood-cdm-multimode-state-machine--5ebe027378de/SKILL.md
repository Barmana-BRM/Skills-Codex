# 木材多模式损伤状态机

## I — 方法论骨架

1. 起始判据、模式归因、演化、删除和事件记录是不同状态机阶段。
2. 同一增量可有多个活动模式；只保留 `argmax` 会丢失并发起损与能量贡献。
3. 所有候选模式都从同一 committed 快照计算，不能让循环顺序改变后续 trial 驱动力。
4. 历史变量和损伤只能不可逆推进；卸载、切步和重试不得恢复或重复触发事件。
5. 应力、全部状态、受损算子、能量、事件和删除标志必须原子提交或整体回滚。
6. 多模式组合规则必须与热力学和六维算子一致，不能靠覆盖槽位解决竞争。

## A2 — 触发与路由

在以下场景调用：

- L/R/T 法向与 LR/LT/RT 剪切模式在同一增量越过阈值。
- 代码用单一最大指标决定模式，次级模式、历史或耗散被覆盖。
- 改变模式循环顺序、cutback 或重试次数后得到不同状态。
- 卸载后触发标志恢复，或 KINC 改变导致旧事件复活。
- 元素删除与模式损伤分开提交，失败后留下半更新输出。

若问题只是位置 ABI，先用 `umat-props-statev-contract`；若是 Tsai-Wu 专用事件语义，使用 `tsai-wu-damage-state-machine`。

## 输入与输出合同

必需输入：模式清单、各模式驱动力和阈值、历史变量、演化律、组合算子、删除规则、回滚协议和事件语义。

输出：

- 版本化状态图与每个状态的合法转移。
- trial/committed 数据结构和活动集规则。
- 首次、当前和最近事件的明确定义。
- 原子提交、失败码和回滚合同。
- 并发模式、卸载、重试和循环顺序测试矩阵。

## E — 执行步骤

1. 冻结模式集合及其材料轴、拉压符号、驱动力、阈值和演化变量。
2. 定义 committed 快照；所有 trial 模式从该快照并行计算。
3. 构造活动集，保留所有越阈模式；若需要主模式，只把它作为派生标签。
4. 分别更新历史、损伤、能量和事件候选，禁止在循环内覆盖 committed 状态。
5. 用声明的组合规则生成六维受损算子，并检查上下界、互易性与可用性。
6. 只有所有模式、算子、能量和删除条件均通过时才原子提交；否则整体回滚。
7. 对模式排列做置换测试，并注入 cutback、重复调用、卸载—再加载和双模式同时触发。
8. 输出状态版本、逐槽语义和迁移限制；无法重建的旧历史不得直接 restart。

## B — 边界

- `argmax` 可以作为显示标签，不能替代多活动模式状态。
- KINC 只是步内增量号，不是永久事件 ID，也不能作为跨步重置依据。
- 元素删除不能早于最终一致状态的形成，也不能在失败路径单独提交。
- 同一阈值附近的 active-set 切换可能不可微，应在切线审计中标记单边列或不可微点。
- 本 skill 不计算强度参数、塑性乘子或 Voigt 映射。
