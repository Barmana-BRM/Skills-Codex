# LLD 审查报告与准出证书模板

本文档提供 LLD 审查的输出参考，遵守 `../../../references/review-boundaries.md`。按模式选用；结构可按信息量裁剪，不因模板额外制造问题、表格或新产物。每条强制 comment 必须包含有效依据、实际失败、影响、最小修复、是否改变边界；缺陷、Evidence gap、Scope decision、P2 分栏。表内适用性、数量和通过状态必须按本次证据填写，不能照抄示例形成默认全绿。

## 有限修复 / 整改 delta 模板

可以直接回复或更新现有 review note，不强制生成新文件、Manifest 或证书。

```markdown
mode: bounded_change
technical_verdict: APPROVED / CHANGES_REQUIRED / EVIDENCE_BLOCKED
scope_status: WITHIN_APPROVED_SCOPE / DECISION_REQUIRED

本轮范围：{方案/变更、原 finding ID、验收语义、直接影响；明确未审部分}
有效依据：{现有批准需求/Contract/HLD/ADR/用户决定；争议边界追溯原始批准人及范围}
评审结果：{原问题关闭证据；如有缺陷，写具体失败与最小边界内修复}
必要证据缺口：{最小 gap 或 NONE；暂停哪些结论、哪些部分可继续}
范围决定：{旧/新行为、产品/工程影响、有权 Owner、边界内选项和建议；或 NONE}
可选 P2：{仅建议，不阻断、不自动结转}
停止与下一步：{仅剩约定 P0/P1/必要 gap；已关闭则停止，不重跑全部历史范围}
权限说明：本结论仅覆盖所列增量；不授权 push、CI、策略/配置发布、共享数据写入或部署。
```

技术可行但 Scope decision 未闭合不能总称准出。Reviewer 旧意见或其派生 APPROVED note 不是新增范围的批准来源；污染基线只撤回受影响声明，不撤销无关有效批准。

## 使用说明

1. **选择模板**：根据审查结果选择对应模板
2. **填充内容**：替换 `{占位符}` 为实际内容
3. **按需表达**：保留必要判定内容，有限评审可用短文，不强制表格和全量证书
4. **证据引用**：所有问题必须指向具体位置（如 `LLD:3.2`、`HLD:4.1`）
