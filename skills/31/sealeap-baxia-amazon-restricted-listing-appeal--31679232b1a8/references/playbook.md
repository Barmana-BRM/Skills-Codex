# Amazon 儿童品类误判申诉 Playbook

## 适用问题

Use for 非儿童品类被误判要求提交儿童合规文件、Listing含敏感年龄词汇的自查、被误判下架后的申诉邮件撰写. Do not use this appeal path for products that are genuinely marketed to or intended for children — those must complete real compliance requirements instead.

## 输入证据

- 目标 marketplace、类目、价格带、上架时间与运营模式
- 候选品与同购买意图可比样本的销量、评论、价格和上架时间
- 关键词需求、历史趋势、广告依赖、同款密度和品牌集中度
- 采购、头程、平台费、退货、仓储、交期和合规/IP 基础信息

## 决策路径

1. 收到合规文件要求或下架通知后，先确认产品设计与营销定位是否本就不面向儿童，若产品确实面向儿童则不走本流程。
2. 逐字检查标题、五点描述、产品描述与后台关键词，标出可能触发误判的年龄或人群相关词汇，逐条判断是否需要删除或改写。
3. 在详情页信息中补充清晰的目标受众说明与不适用低龄人群的提示，确保修改后的页面表述前后一致。
4. 修改生效后撰写申诉说明，逐条对应本次修改内容与整改结果，避免笼统陈述。
5. 提交申诉后跟踪处理结果，若被驳回需核对是否还有遗漏的敏感表述或图片文字，补充材料后再次申诉。
6. 把本次触发误判的具体词汇与页面位置记录下来，用于其余相似Listing的预防性自查。

## 经验假设与降级规则

- 触发误判的具体关键词清单会随平台合规规则调整而变化，需以当前后台提示或政策页面为准，不能只套用一次性总结的词表。
- 误判涉及的品类范围是来源观察到的现象，不代表全部受影响类目，需按自己账户收到的具体通知判断适用范围。
- 申诉说明需要结合自己账户的真实情况改写，不能整段照抄同一模板，避免出现与实际产品不符的表述。

- 出现固定阈值、平台算法解释或因果结论时，改为待验证假设，并用当前站点与账户数据校准。
- 数据源冲突时保留各自口径，不取没有依据的平均数，也不选择更好看的结果。
- 第三方工具不可用、额度不足或 schema 改变时，记录缺口并停止；不得伪造调用结果。

## 输出检查

- 敏感词汇自查清单
- Listing修改前后对照记录
- 申诉说明文本
- 同类Listing预防性自查表
- 每项建议都能回指当前任务中的证据或明确假设。
- 对未授权的线上变更保留草案；用户已有授权覆盖明确对象、动作与预算时可执行，并记录实际结果与回读证据。

## 指标口径补充

- 所有比率先统一站点、货币、对象、流量范围与归因窗口；分母为零或缺失时记为不可计算，不能解释为零成本或无限效率。
