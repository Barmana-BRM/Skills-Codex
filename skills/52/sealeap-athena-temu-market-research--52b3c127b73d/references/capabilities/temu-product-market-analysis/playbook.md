# Temu 商品市场分析执行手册

## 任务判断

从检索到单商品趋势分析，结合规格和价格判断需求变化。

## 输入核对

| 输入维度 | 检查方式 |
|---|---|
| 本任务字段 | 国家、关键词或商品、期间、价格和规格 |
| 对象 | 将自然语言对象对应到可验证 ID、SKU、文件或文献，多个候选不任意挑选 |
| 期间与范围 | 数据期、采集时间、时区、样本上限和分页情况分别记录 |
| 工具 | 按 [工具路由](tool-routing.md) 核对实际连接、schema、权限与费用 |

## 业务核验

- 销量为估计时标明。
- 暂时补贴不能当长期毛利依据。

## 建议交付结构

1. 商品样本、趋势和经济性缺口。
2. 逐项数据表：对象、实际值、单位/币种、来源、数据期、证据状态与缺失原因。
3. 判断：哪些证据支持结论，哪些是估计或假设，哪些结论因缺口尚不能形成。
4. 动作：已有授权范围、预览、实际执行状态、回读及剩余任务。
5. 文件交付时给出可打开的文件路径；数据、图表与文字结论相互核对。


## 数据与输出契约

每个实测或引用记录保留 `platform`、`marketplace`、`entity_id`、`data_period`、`collected_at`、`source`、`metric_definition` 和 `evidence_status`。来源记录的是本次使用的实际工具、业务文件或官方页面，不能隐去真实数据来源。凭证和个人联系方式不进入交付。

- `FACT`：当前页面观察、可回读的账户事实或原始文件明确记载的内容。
- `ESTIMATE`：第三方销量、需求、曝光等模型估计；保留提供方原始定义。
- `ASSUMPTION`：待检验的假设、语言模型建议、推测关系。
- `UNKNOWN`：未取得、字段未返回、访问失败或无法解释的数据；数值用 `null`，同时写 `missing_reason`。

按平台、市场、时间窗、币种、单位和变体粒度对齐后才计算。不能将抓取时间当业务发生时间，也不能把未覆盖日期填成零。合并结果保留各信源原值，避免为了得到一致结论抹平差异。

文件只在用户任务需要保存时写入明确的输出目录，不默认落在 Skill 安装目录。用户要求仅查看时不新建数据库、远程报告或上传文件。若需要入库，先使用结构化写入，再回读条数与关键字段；查询成功不等于保存成功。


## 执行状态与恢复

写操作前形成可核对的对象、原值、新值、费用或影响、停止条件与回退方案。先核对会话已有授权；已覆盖对象、动作和金额时继续执行并回读，只有缺失或扩大范围时请求补充授权。普通的“分析一下”不包含下单、发布、退款或调整广告的授权。

HTTP 成功、业务受理、异步处理完成和最终生效分别记录。超时或部分失败时保留请求/任务 ID、已成功的对象与可脱敏结果，先查状态再决定重试；不自动重发非幂等动作。读取重试遵守提供方限流及用户给定的额度，不擅自换账户或扩大样本。

`READY` 表示本次任务的输入、工具与权限已足够；`HOLD` 表示已完成可独立部分且有明确缺口；`STOP` 表示当前目标或数据存在不能继续处理的冲突。`READY` 不代表线上动作已经完成；执行结果另列 `not_started / draft / submitted / succeeded / partially_succeeded / failed`。
